# 启动方式速查手册

> 本文档面向新手，说明本项目所有启动方式的区别和使用场景。看完就能知道「什么时候该用什么命令」。

---

## 一、三种启动方式速览

| 方式 | 配置文件 | 用途 | 镜像来源 | 前端是否热更新 |
|------|---------|------|---------|---------------|
| **开发环境** | `docker-compose.dev.yml` | 日常开发、改代码、联调 | 直接挂载本地源码 | 需手动构建 |
| **生产环境** | `docker-compose.yml` | 本地验证生产构建 | 从源码编译打包 | 否（在镜像里） |
| **交付环境** | `deliver/docker-compose.yml` | 模拟客户真实部署 | 导入的镜像包 | 否（在镜像里） |

**一句话总结**：
- 要**改代码** → 用开发环境
- 要**确认打包没问题** → 用生产环境
- 要**给客户演示** → 用交付环境

---

## 二、前置条件（所有方式通用）

1. Docker + Docker Compose 已安装
2. 端口未被占用（3306、8080、7070）
3. `.env` 文件已配置（复制 `.env.example` 并修改密码）

---

## 三、开发环境（日常开发首选）

### 适用场景
- 修改后端 Java 代码
- 修改前端 Vue 页面
- 接口联调测试
- 数据库调试

### 启动步骤

```bash
cd clinic-saas-source/docker

# 启动全部服务（MySQL + 后端 + 前端）
docker compose -f docker-compose.dev.yml up -d
```

首次启动会比较慢，因为后端容器需要下载 Maven 依赖。

### 验证启动成功

```bash
docker compose -f docker-compose.dev.yml ps
```

应看到三个容器都是 `Up` 状态：
- `clinic-mysql-dev` (healthy)
- `clinic-backend-dev`
- `clinic-frontend-dev`

访问 `http://localhost:7070` 看到登录页面即成功。

### 修改代码后的操作

| 你改了什么 | 需要执行的操作 |
|-----------|--------------|
| 后端 Java 代码 | `docker compose -f docker-compose.dev.yml exec backend mvn compile -q` |
| 前端 Vue/CSS/JS | `cd ../saas-vue-src && npm run build`，然后 `docker compose -f docker-compose.dev.yml restart frontend` |
| 前端页面在开发时频繁修改 | 见下方「前端开发提速」 |
| Dockerfile 或新增系统依赖 | `docker compose -f docker-compose.dev.yml up -d --build` |

### 前端开发提速

频繁修改前端时，每次 `npm run build` 很慢。可以在 `saas-vue-src/` 目录下单独启动 Vue 开发服务器：

```bash
cd saas-vue-src
npm run serve
```

然后访问 `http://localhost:7070`（Nginx 代理）或 `http://localhost:8081`（Vue 开发服务器直出），修改代码后自动热刷新。

> 注意：`npm run serve` 只在宿主机运行前端，后端仍需 Docker 启动。

### 停止开发环境

```bash
cd clinic-saas-source/docker
docker compose -f docker-compose.dev.yml down
```

## 四、生产环境（打包验证）

### 适用场景
- 确认 Dockerfile 能正常构建
- 验证前后端打包产物是否正确
- 发布前本地预演

### 启动步骤

```bash
cd clinic-saas-source/docker

# 构建镜像并启动（会编译前后端源码）
docker compose up -d --build
```

构建过程需要几分钟，前端 `npm install` + `npm run build`，后端 `mvn package`。

### 与开发环境的区别

| 对比项 | 开发环境 | 生产环境 |
|-------|---------|---------|
| 后端 | 容器内直接运行 `mvn spring-boot:run`，挂载源码 | 编译成 JAR 包运行在容器内 |
| 前端 | 挂载本地 `dist/` 目录 | 编译进 Nginx 镜像 |
| 修改代码后 | 热更新或重启容器 | 必须重新 `--build` |
| 启动速度 | 快（依赖已缓存） | 慢（需完整编译） |

### 停止生产环境

```bash
cd clinic-saas-source/docker
docker compose down
```

## 五、交付环境（模拟客户部署）

### 适用场景
- 给客户演示
- 验证交付包（`clinic-saas-images.tar`）是否完整
- 测试导入镜像后的启动流程

### 前置准备

确保 `deliver/` 目录下有这些文件：
- `clinic-saas-images.tar`（镜像包）
- `docker-compose.yml`
- `.env`
- `sql/init/database_init.sql`

如果没有镜像，先导入：

```bash
cd clinic-saas-source/docker/deliver
docker load -i clinic-saas-images.tar
```

### 启动步骤

```bash
cd clinic-saas-source/docker/deliver
docker compose up -d
```

### 与生产环境的区别

交付环境使用**预先打包好的镜像**，不需要从源码编译。客户拿到交付包后，只需导入镜像、配置 `.env`、启动即可。

### 停止交付环境

```bash
cd clinic-saas-source/docker/deliver
docker compose down
```

## 六、环境切换脚本（一键操作）

如果你不想记命令，可以使用交互式脚本：

```bash
cd clinic-saas-source/docker
./scripts/环境切换.sh
```

菜单选项：
- `dev` — 启动开发环境
- `prod` — 启动生产环境
- `stop` — 停止当前环境
- `status` — 查看容器状态

也可以直接传参数跳过菜单：

```bash
./scripts/环境切换.sh dev     # 直接启动开发环境
./scripts/环境切换.sh prod    # 直接启动生产环境
./scripts/环境切换.sh stop    # 停止
```

## 七、常见问题

### Q1：启动时提示 "port is already allocated"

**原因**：3306、8080 或 7070 端口被其他程序占用。

**解决**：
```bash
# 查看谁占用了 3306
lsof -i :3306

# 如果是之前的容器没停干净
docker ps
docker stop <容器名>
```

### Q2：开发环境启动后前端页面空白

**原因**：`saas-vue-src/dist/` 目录不存在或为空。

**解决**：
```bash
cd saas-vue-src
npm install
npm run build
cd ../docker
docker compose -f docker-compose.dev.yml restart frontend
```

### Q3：后端热更新不生效

**原因**：`spring-boot-devtools` 没有检测到文件变化。

**解决**：确保执行了 `mvn compile -q`，且修改的是 `.java` 文件。

### Q4：交付环境 MySQL 提示 "unhealthy"

**原因**：可能是 `sql/init/database_init.sql` 文件缺失或路径不对。

**解决**：
```bash
# 检查 deliver/sql/init/ 下是否有 database_init.sql
ls deliver/sql/init/

# 如果没有，从 docker/sql/init/ 复制
mkdir -p deliver/sql/init
cp docker/sql/init/database_init.sql deliver/sql/init/

# 删除旧数据卷后重新启动
rm -rf deliver/mysql-data
cd deliver && docker compose up -d
```

### Q5：怎么切换回另一种环境？

**必须先把当前环境停掉**，再启动另一种：

```bash
# 假设当前在开发环境
docker compose -f docker-compose.dev.yml down

# 然后启动生产环境
docker compose up -d --build
```

**不要同时运行两套环境**，会端口冲突。

## 八、服务地址速查

无论哪种启动方式，服务地址都一样：

| 服务 | 地址 |
|------|------|
| 前端页面 | `http://localhost:7070` |
| 后端 API | `http://localhost:8080` |
| Swagger 文档 | `http://localhost:8080/swagger-ui.html` |
| MySQL | `localhost:3306`（开发）/ `localhost:3307`（交付，如修改过） |
