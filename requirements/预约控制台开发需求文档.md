## 一、现状分析与问题汇总

### 1.1 业务流程现状

当前系统核心业务流为：

```
登录 → 首页概览 → 患者列表 → 患者详情(360视图) → 病历/预约/收费
         ↓
    预约工作台（缺少入口）
```

**核心问题**：预约工作台（`/Appointment`）路由已注册，但左侧导航菜单未配置入口，导致用户无法从界面进入预约管理页面。

### 1.2 问题清单

| 优先级 | 问题描述 | 影响范围 | 现状 |
|--------|----------|----------|------|
| P0 | 预约工作台无前端入口 | 全局导航 | `roleMenuCatalog.js` 中只注册了 `/Appointment2`（预约列表），缺少 `/Appointment`（预约工作台）菜单项 |
| P0 | 新增预约弹窗交互异常 | AppointmentView | 弹窗打开后整体呈灰色，必须再点击一次才能正常输入；疑似遮罩层 z-index 或 focus 问题 |
| P0 | 手机号无法在新建患者时输入 | PatientView | 新建患者弹窗中手机号字段可能存在 focus 冲突或事件拦截 |
| P1 | 日历视图缺少双击新增预约 | AppointmentView | 目前仅支持点击"新增预约"按钮，不符合快捷操作习惯 |
| P1 | 日历视图点击患者姓名无反应 | AppointmentView | 应跳转到患者 360 详情页 |
| P1 | 预约目的字段语义不准确 | AppointmentView | "预约目的"应改为"预约项目"，更贴合口腔门诊业务 |
| P1 | 医生姓名字段未支持下拉选择 | AppointmentView | 当前为文本输入，应改为下拉选择，数据源为系统中已有医生 |
| P2 | 新建患者交互不够友好 | PatientView | 表单字段较多，缺少分步引导或智能提示 |
| P2 | 患者列表缺少直接新建患者入口 | PatientView | 侧边栏底部虽有按钮，但表单交互需优化 |

### 2.2 新增预约弹窗修复（P0）

**需求编号**：DLG-001

**描述**：修复新增/编辑预约弹窗打开后界面灰色、无法直接输入的问题。

**根因分析**：
- 当前弹窗未设置 `append-to-body` 属性，可能导致 `el-dialog` 被父级元素的样式或遮罩层遮挡
- 或者 `.el-dialog__wrapper` 的 `z-index` 被页面其他元素覆盖

**具体改动**：
- 文件：`src/views/Manager/AppointmentView.vue`
- 在 `<el-dialog>` 标签上增加属性：
  ```vue
  <el-dialog
    :title="isEditing ? '编辑预约' : '新增预约'"
    :visible.sync="dialogVisible"
    width="560px"
    custom-class="appt-dialog"
    append-to-body
    :modal-append-to-body="true"
  >
  ```
- 增加 `appt-dialog` 的 CSS 样式，确保 `z-index` 层级正确：
  ```css
  .appt-dialog {
    z-index: 2000 !important;
  }
  .appt-dialog .el-dialog__wrapper {
    z-index: 2000 !important;
  }
  ```

**验收标准**：
- [x] 点击"新增预约"按钮后弹窗立即正常显示，无需二次点击
- [x] 弹窗内所有输入框（患者姓名、日期、时间、医生、项目、状态）均可直接输入
- [x] 弹窗关闭后再次打开仍保持正常

validatePatient() {
  const errors = []
  if (!normalizeText(this.editItem.name)) errors.push('患者姓名必填')
  if (!this.editItem.gender) errors.push('患者性别必选')
  if (!this.editItem.age && this.editItem.age !== 0) errors.push('患者年龄必填')
  const phone = normalizeText(this.editItem.phone)

  if (!this.editItem.customer_source) errors.push('患者来源必选')
  return errors
}
