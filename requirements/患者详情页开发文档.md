## 一、页面概述

患者详情页是系统的核心页面之一，承载患者全生命周期信息的展示与管理。用户从预约工作台、患者列表、日历视图等入口点击患者姓名后跳转至此页面。

### 1.1 页面定位

| 项目 | 说明 |
|------|------|
| 页面名称 | 患者360视图 |
| 路由路径 | `/Patient360` |
| 入口参数 | `query.id`（患者ID，必填）、`query.tab`（默认Tab，可选）、`query.name`（患者姓名，可选） |
| 权限角色 | admin / doctor / nurse |

### 1.2 核心功能

- 展示患者基础档案、就诊统计、风险标签
- 管理病历记录（新增/编辑/删除/模板库）
- 管理预约信息（新增/编辑）
- 管理处置收费（新增处置/收费/退款）
- 管理影像资料（上传/查看/发送患者/删除）
- 管理回访计划（新增/删除）
- 管理知情同意书（下发/查看签署状态）
- 展示患者时间线（就诊/治疗/随访/预约事件聚合）

## 三、页面布局结构

### 3.1 整体布局

参考 e看牙 患者详情页与现有系统实现，采用 **上下结构 + Tab 内容区** 模式：

```
┌─────────────────────────────────────────────────────────────┐
│  顶栏（返回 + 标题 + 快捷搜索）                               │  ← 40px
├─────────────────────────────────────────────────────────────┤
│  ┌────────────────────────────────────┐  ┌────┐┌────┐...   │
│  │ 患者档案卡（头像/姓名/基本信息）      │  │统计││统计│     │  ← 自适应
│  └────────────────────────────────────┘  └────┘└────┘      │
├─────────────────────────────────────────────────────────────┤
│  风险标签行（手动标签 + 智能洞察标签）                         │  ← ~44px
├─────────────────────────────────────────────────────────────┤
│  ┌─────────────────────────────────────────────────────┐   │
│  │ Tab 导航栏（病历/预约/收费/影像/回访/知情同意/时间线） │   │  ← ~40px
│  ├─────────────────────────────────────────────────────┤   │
│  │                                                     │   │
│  │                   Tab 内容区域                       │   │  ← 自适应
│  │                                                     │   │
│  └─────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 布局要点

- **顶栏**：固定高度，背景白色，底部 1px 边框分隔
- **档案卡 + 统计卡片**：横向 flex 排列，gap 12px，档案卡 flex:1 自适应
- **风险标签行**：白色背景卡片，圆角 4px，横向排列可换行
- **Tab 区**：`el-tabs type="border-card"`，内容区自适应高度，内部可滚动

## 四、各区域详细规范

### 4.1 顶栏

| 元素 | 说明 |
|------|------|
| 返回按钮 | `el-button` icon="el-icon-arrow-left"，点击调用 `$router.back()`，确保从任何入口返回都能回到上一页 |
| 页面标题 | "患者360视图"，font-size:16px，font-weight:600 |
| 患者ID输入 | `el-input` width:110px，type="number"，支持手动输入其他患者ID快速切换 |
| 查看按钮 | `el-button type="primary"`，触发 `load360()` |

**交互规范**：
- 返回按钮必须使用 `$router.back()`，禁止硬编码跳转路径（如 `/Patient`）
- 路由参数变化时（`$route.query.id`），自动重新加载患者数据

### 4.2 患者档案卡

**容器**：`el-card` shadow="never"，圆角 12px，白色背景，阴影 `var(--shadow-card)`

**Header 区域**：
- 左侧：头像（`el-avatar` :size="48"）+ 患者姓名（font-size:18px, font-weight:600）+ 性别标签（`el-tag` size="mini" effect="plain"）
- 右侧："修改资料"按钮（`el-button type="primary" plain size="mini" icon="el-icon-edit" round`）

**Body 区域**：`el-descriptions` :column="3" border size="mini"

| 标签 | 字段 | 说明 |
|------|------|------|
| 姓名 | `data.patient.name` | 纯展示 |
| 性别 | `data.patient.gender` | 纯展示 |
| 手机 | `data.patient.phone` | 纯展示 |
| 年龄 | `formatAge(data.patient)` | 纯展示 |
| 患者来源 | `data.patient.customer_source` | 空值显示 "-" |
| 患者关系 | `data.patient.relation_type` + 关联患者 | 有关联时显示为可点击文字链接，跳转关联患者360 |
| 介绍人 | `referralDisplayText`（计算属性） | 支持内部患者/外部介绍人/未填写 |

**欠费横幅**（条件渲染）：
- 当 `data.hasArrears` 为 true 时显示
- 背景：`rgba(255,149,0,0.08)`，边框：`rgba(255,149,0,0.15)`
- 内容：警告图标 + "当前欠费 **¥{金额}**"

**公众号绑定面板**：
- 顶部：标题"公众号绑定" + 描述 + 状态标签（`el-tag` :type="wechatBound ? 'success' : 'info'"）
- 未绑定：左侧二维码区域（220x220）+ 右侧操作按钮（打开绑定链接/复制绑定链接）+ 提示文字
- 已绑定：绿色提示条"该患者已完成微信公众号绑定..."

### 4.3 统计卡片

**容器**：横向 flex，gap:10px，flex-shrink:0

**单张卡片样式**：
- 背景白色，圆角 8px，边框 1px solid var(--border-color)
- padding:14px 18px，min-width:100px，text-align:center
- 阴影：`var(--shadow-card)`，hover 时 transform:translateY(-4px)

| 卡片 | 数据字段 | 数值样式 |
|------|----------|----------|
| 就诊次数 | `data.visitCount` | font-size:24px，color:var(--primary) |
| 治疗次数 | `data.treatments.length` | font-size:24px，color:var(--primary) |
| 累计费用 | `totalFeeDisplay`（计算属性） | font-size:20px，color:var(--warning) |
| 最近就诊 | `formatDate(data.lastVisit)` | font-size:16px，color:var(--success) |
| 下次随访 | `formatDate(data.nextFollowup)` | font-size:16px，color:var(--success) |

### 4.4 风险标签行

**容器**：白色背景卡片，圆角 4px，padding:10px 16px，横向 flex 排列可换行

| 元素 | 说明 |
|------|------|
| 标签前缀 | "风险标签："，font-size:13px，color:var(--text-secondary) |
| 手动标签 | `data.riskTags` 循环渲染，`el-tag` size="small"，根据 risk_level 显示 danger/warning/默认，支持 closable |
| 智能洞察标签 | 高价值客户（success）、流失风险（danger）、口碑客户（warning） |
| 添加按钮 | `el-button size="mini" type="text" icon="el-icon-plus"` |
| 空状态 | "暂无"，color:#999，font-size:12px |

## 八、交互规范

### 8.1 返回逻辑

- 顶栏返回按钮必须调用 `$router.back()`
- 禁止硬编码 `$router.push('/Patient')`，确保从预约工作台进入后返回预约工作台

### 8.2 弹窗层级

- 所有 `el-dialog` 必须设置 `append-to-body` 属性
- 病历弹窗等特殊全宽弹窗需设置 `:close-on-click-modal="false"` 防止误关闭

### 8.3 患者跳转

- 患者档案卡中的"关联患者"姓名应为可点击链接，点击后跳转该患者的360视图
- 任何展示患者姓名的位置（如病历中的患者姓名）应支持跳转（如适用）

### 8.4 离线缓存

- 患者360数据使用 `fetchCachedResource` 加载，支持离线缓存
- 本地患者ID（离线创建）需通过 `tryResolveLocalPatientRoute` 自动映射为服务端ID

### 8.5 数据加载状态

- 加载中显示 `el-icon-loading` 居中大图标
- 数据为空时显示对应空状态提示，避免空白页面

### 8.6 操作反馈

- 新增/编辑/删除成功后显示 `this.$message.success('xxx成功')`
- 失败时显示错误信息 `this.$message.error(msg || '操作失败')`
- 危险操作（删除）前需 `this.$confirm` 二次确认

## 十一、开发注意事项

1. **数据一致性**：患者360总览接口返回的数据为聚合数据，部分Tab（如病历）可能需要单独调接口获取最新列表
2. **弹窗关闭后刷新**：大多数弹窗操作成功后需调用 `load360()` 刷新数据，病历操作后额外调用 `loadRecords()`
3. **医生下拉数据源**：统一从 `/accounts/doctors/active` 获取，避免硬编码
4. **金额格式化**：所有金额展示使用 `formatMoney()` 方法，保留两位小数
5. **日期格式化**：使用统一的 `formatDate()` / `formatDateTime()` / `formatTime()` 方法
6. **本地患者兼容**：离线模式下创建的患者可能使用本地ID，需通过 `isLocalEntityId` 和 `resolveMappedServerId` 处理
7. **病历模板分类**：默认分类为"常用模板"，支持按分类筛选和搜索
