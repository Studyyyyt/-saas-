## 修复分组与子代理分配

### 子代理 A：安全与性能修复组（AiProxyController + settings）

**负责文件**：
- `clinic-saas-source/saas-springboot-src/src/main/java/com/example/springboot/controller/AiProxyController.java`
- `~/.claude/settings.json`

**修复任务**：
1. **P1 - settings.json API Token 安全**：将明文 `ANTHROPIC_AUTH_TOKEN` 改为从环境变量读取，settings.json 中只保留 `"ANTHROPIC_AUTH_TOKEN": "${ANTHROPIC_AUTH_TOKEN}"` 或删除该字段（优先读取系统环境变量）。
2. **P2 - 全局配置缓存**：`smartExtract` 中每次调用 `aiGlobalConfigMapper.selectByKey("response_field")` 改为在 `@PostConstruct` 中加载到内存字段（`private volatile String globalResponseField`），提供刷新方法。
3. **P5 - ObjectMapper 复用**：将 `new ObjectMapper()` 改为注入 Spring 的 `ObjectMapper` bean（`private final ObjectMapper objectMapper` 构造函数注入）。
4. **P6 - SSE 线程池**：将 `new Thread(() -> ...).start()` 改为使用 `ExecutorService`（`Executors.newCachedThreadPool()` 或 Spring `@Async`）。
5. **P9 - 包名一致**：将 `com.example.springboot.mapper.AiAgentConfigMapper` 完整包名改为 import 声明。
6. **P10 - 异常日志**：`catch (Exception ignored)` 改为 `catch (Exception e)` 并添加 `log.warn(...)`。

### 子代理 B：OpenDataController 修复组

**负责文件**：
- `clinic-saas-source/saas-springboot-src/src/main/java/com/example/springboot/controller/OpenDataController.java`

**修复任务**：
1. **P4 - getFollowups 分页修复**：将 Java 层过滤逻辑（patientName、startDate、endDate）下沉到 `PatientFollowupMapper.search` SQL 中，删除 Java 层过滤，让 PageHelper 正确统计 total。
2. **P8 - getPatientGroups 手动分页**：改为使用 PageHelper 分页，或在 Mapper 中完成分页查询，删除手动计算 fromIndex/toIndex/pages 逻辑。
3. **P10 - 异常日志**：所有 `catch (Exception ignored)` 添加 warn 日志。
4. **附加修复**：`parseDate` 方法添加日志记录解析失败情况；`arrearsAmount > 0.0001` 改为使用 `BigDecimal` 比较。

### 子代理 C：校验与架构修复组

**负责文件**：
- `clinic-saas-source/saas-springboot-src/src/main/java/com/example/springboot/controller/AiConfigController.java`
- `clinic-saas-source/saas-springboot-src/src/main/java/com/example/springboot/controller/OpenDataController.java`

**修复任务**：
1. **P7 - AiConfigController 登录态校验**：为 4 个接口添加 `account_id` 校验（参考 `AiProxyController` 的校验逻辑）。
2. **P3 - OpenDataController 依赖拆分**：将 25 个依赖按业务域拆分为 3 个内部 Service（`OpenPatientService`、`OpenFinanceService`、`OpenMaterialService`），Controller 只保留路由和参数校验，业务逻辑下沉到 Service。注意：这是一个中等规模的重构，优先提取患者相关（PatientService、PatientMapper、MedicalRecordService 等）到一个 Service。

## 并行修复执行指令

**执行方式**：调用 3 个子代理（Agent）并行执行上述修复任务。每个子代理独立工作，互不阻塞。

**验证要求**：
- 每个子代理修复完成后，执行 `mvn compile -q` 验证编译通过
- 修复完成后由主代理汇总所有变更

## 修复顺序与依赖

- 子代理 A、B、C 互相独立，可完全并行
- 子代理 C 中的 OpenDataController 拆分与子代理 B 的 OpenDataController 修改可能冲突，建议：
  - 子代理 B 只修改方法内部逻辑（分页、日志）
  - 子代理 C 只修改类结构和依赖注入（提取 Service）
  - 两者修改范围不重叠
