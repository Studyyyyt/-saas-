## 一、系统概述

口腔门诊 SaaS 管理系统，面向口腔诊所/牙科门诊，覆盖患者管理、预约排班、电子病历、治疗收费、耗材库存、义齿加工、经营分析、咨询营销等核心业务场景。

**系统入口**：
- **管理后台**（PC 桌面端）：Vue 2 单页应用，医生/护士/管理员日常使用
- **AI 智能中心**：集成在管理后台首页，通过 n8n 工作流调用各类 AI 模型
- **MCP Data Server**：外部数据接口层，供 Claude Code CLI 查询诊所数据

**微信门户和员工 H5 工作台已移除**，系统当前以 PC 管理后台为核心。

- n8n 独立部署，通过 frp 访问
- 本地不运行 Nginx 反向代理（SSL/域名由云服务器处理）

### 5.2 关键服务说明

| Service | 职责 |
|---------|------|
| `AccountService` | 账号 CRUD、按用户名+密码明文认证 |
| `PatientService` | 患者档案、微信 OpenID 绑定（字段保留） |
| `MedicalRecordService` | 病历增删改查 |
| `AppointmentService` | 预约管理、状态流转 |
| `TreatmentService` | 治疗处置、收费、退款 |
| `FinanceService` | 财务流水、医生业绩统计 |
| `AiProxyService` | **AI 统一代理**：将前端请求转发到外部 Webhook（n8n） |
| `BusinessDailyAnalysisService` | 经营日报/周报/月报生成，规则引擎分析（不调用 OpenAI） |
| `WechatWorkWebhookService` | 企业微信机器人通知（可选） |

### 5.3 登录与鉴权

- **登录方式**：`POST /auth/login`，接收 `username` + `password`
- **密码存储**：明文存储（数据库中 `password` 字段为明文）
- **会话管理**：**无 JWT / Session**，前端保存用户信息，后续请求通过 `X-Operator-Account-Id` 或 `account_id` 参数传递身份
- **权限控制**：三级角色（`admin` / `doctor` / `nurse`），前端根据 `allowedMenuKeys` 控制菜单显示；后端**无统一接口鉴权拦截器**
- **敏感操作**：删除患者/病历需二级密码（`security.patient-admin-secondary-password`）

### 6.2 状态管理

- **无 Vuex / Pinia**
- 登录状态：`sessionStorage` / `localStorage` + 自定义事件
- 离线状态：`Vue.observable` 响应式对象（`src/utils/offline/network.js`）

### 6.3 离线支持

基于 **Dexie.js**（IndexedDB）实现离线优先架构：
- **缓存层**：GET 请求自动缓存，网络失败时回退缓存（保留 14 天）
- **队列层**：断网时患者/预约/病历的新增/编辑操作入队
- **同步层**：网络恢复后自动按优先级同步（`patient -> appointment -> medicalRecord`）

## 八、AI 架构（重点）

### 8.1 架构原则

**系统不直接调用 OpenAI API，所有 AI 能力通过 n8n 工作流间接调用。**

```
前端页面 ──→ AiProxyController ──→ AiProxyService ──→ n8n Webhook ──→ AI 模型（OpenAI/Claude/DeepSeek）
                (/api/ai/proxy/{agentKey})
```

### 8.2 AI 代理（AgentKey）

系统预定义了 22 个 AI Agent，覆盖诊所全业务场景：

| AgentKey | 用途 |
|---------|------|
| `medical-expand` | 病历扩写 |
| `patient-insight` | 患者洞察分析 |
| `appointment-assist` | 预约辅助 |
| `consultation-assist` | 咨询辅助 |
| `business-analysis` | 经营分析对话 |
| `financial-analysis` | 财务分析 |
| `lab-statistics-analysis` | 加工统计 |
| `material-inventory-assist` | 库存辅助 |
| `home-assistant` | 首页 AI 助手 |
| `doctor-schedule` | 排班建议 |

每个 Agent 在 `ai_agent_config` 表中配置：
- `endpoint_url`：n8n Webhook 地址
- `auth_type` / `auth_token`：认证方式
- `request_template`：请求模板
- `response_type`：`json` 或 `sse`

### 8.3 经营日报/周报/月报

`BusinessDailyAnalysisService` 生成经营分析报告：
- **默认模式**（`openai.enabled=false`）：使用**规则引擎**分析，基于预设公式计算经营评分、趋势、风险点
- **AI 模式**（`openai.enabled=true`）：调用 OpenAI API 生成自然语言分析（当前未启用）

**当前系统使用规则引擎模式，不调用 OpenAI。**

### 8.4 MCP Data Server

独立 Python 服务，通过 stdio 模式连接 Claude Code CLI：
- 18 个业务查询工具（患者、预约、病历、财务、库存等）
- 直接读取 MySQL 数据库或调用后端 API
- **与 SaaS 系统服务分离启动**，互不依赖

## 十、单台电脑完整启动指南

以下步骤适用于在同一台电脑（Mac/PC）上启动全部服务。

### 前置条件

- Docker + Docker Compose 已安装
- 至少 4GB 可用内存
- 端口 3306、8080、7070、5678、8000 未被占用

### 10.1 准备环境变量

**诊所系统**（`shuao-clinic-saas-source/docker/.env`）：
```bash
cd shuao-clinic-saas-source/docker
cp .env.example .env
# 修改 DB_PASSWORD、DB_ROOT_PASSWORD、SECURITY_PATIENT_ADMIN_SECONDARY_PASSWORD
```

**n8n**（`n8n/.env`）：
```bash
cd n8n
cp .env.example .env
# 修改 N8N_BASIC_AUTH_PASSWORD
# WEBHOOK_URL 保持默认 http://localhost:5678/（本机部署时）
```

**MCP Data Server**（`mcp-data-server/.env`）：
```bash
cd mcp-data-server
cp .env.example .env
# 修改 JAVA_API_BASE=http://host.docker.internal:8080（Mac）
# 或 JAVA_API_BASE=http://宿主机IP:8080（Linux）
# 修改 OPERATOR_ACCOUNT_ID=1（管理员账号）
```

### 10.2 启动服务（按顺序）

**第 1 步：启动诊所系统（MySQL + 后端 + 前端）**

```bash
cd shuao-clinic-saas-source/docker
./启动生产环境.sh
```

等待约 60 秒，确认后端健康检查通过：
```bash
docker compose ps
# clinic-backend 状态应为 healthy
```

**第 2 步：启动 n8n 工作流平台**

```bash
cd n8n
docker compose up -d
```

验证：
```bash
docker compose ps
# 访问 http://localhost:5678 确认 n8n 界面正常
```

**第 3 步：启动 MCP Data Server**

```bash
cd mcp-data-server
docker compose up -d
```

验证：
```bash
docker compose ps
curl http://localhost:8000/sse
# 应返回 200
```

### 10.3 服务访问地址汇总

| 服务 | 地址 | 说明 |
|------|------|------|
| 诊所前端 | `http://localhost:7070` | PC 管理后台 |
| 诊所后端 API | `http://localhost:8080` | Spring Boot |
| n8n | `http://localhost:5678` | AI 工作流平台 |
| MCP SSE | `http://localhost:8000/sse` | 供 Claude Desktop/Cursor 连接 |
| MySQL | `localhost:3306` | 数据库 |

### 10.4 停止所有服务

```bash
# 停止 MCP
cd mcp-data-server && docker compose down

# 停止 n8n
cd n8n && docker compose down

# 停止诊所系统
cd shuao-clinic-saas-source/docker && docker compose down
```

### 10.5 切换开发/生产环境

```bash
cd shuao-clinic-saas-source/docker

# 切换到开发环境（代码热更新）
./启动开发环境.sh

# 切换到生产环境（构建镜像）
./启动生产环境.sh

# 查看当前状态
./环境切换.sh status
```

## 十二、常见问题

**Q：前端访问后端 API 返回 502？**
A：检查前端容器内的 nginx.conf 是否正确代理了后端路径。修改后需重新构建前端镜像。

**Q：MySQL 初始化脚本为什么没有执行？**
A：`database_init.sql` 只在 MySQL 数据目录首次为空时执行。如需重置数据库，先删除 `./mysql-data` 目录再启动。

**Q：AI 功能如何配置？**
A：在「系统设置 → AI 智能中心」中配置每个 Agent 的 Webhook 地址（指向 n8n），无需填写 OpenAI API Key。

**Q：如何备份数据库？**
A：
```bash
docker exec clinic-mysql mysqldump -u root -p你的密码 clinic_system > 备份.sql
```
