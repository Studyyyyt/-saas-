# 系统维护说明

## Docker 开发环境

### 启动

```bash
cd clinic-saas-source/docker
docker compose -f docker-compose.dev.yml up -d
```

- 后端：`http://localhost:8080`
- 前端：`http://localhost:7070`

### 停止

```bash
cd clinic-saas-source/docker
docker compose -f docker-compose.dev.yml down
```

### 查看日志

```bash
docker compose -f docker-compose.dev.yml logs -f backend
docker compose -f docker-compose.dev.yml logs -f frontend
```

### 重新构建

仅在修改 Dockerfile、docker-compose 文件或新增系统级依赖时使用：

```bash
docker compose -f docker-compose.dev.yml up -d --build
```

## 后端热重载

项目已配置 `spring-boot-devtools`，修改 Java 代码后无需重启容器：

```bash
cd clinic-saas-source/docker
docker compose -f docker-compose.dev.yml exec backend mvn compile -q
```

约 0.3 秒后自动热重启。

## 前端构建

仅用于打包验证，不用于启动服务：

```bash
cd clinic-saas-source/saas-vue-src
npm install
npm run build
```

输出到 `dist/` 目录。

## 数据库迁移

使用 Flyway，迁移脚本位于 `saas-springboot-src/src/main/resources/db/migration/`。

- 版本从 V1 到 V65+
- 启动时自动执行
- 新增迁移脚本遵循 `V{版本号}__{描述}.sql` 命名规范

## 新增 AI Agent 配置步骤

### 前提说明

当前系统采用 **Agent 配置 + 系统功能绑定** 两级架构：

- **Agent 配置**：定义外部工作流（Webhook 地址、认证、请求模板等）。
- **系统功能绑定**：将系统功能（如病历扩写、咨询辅助）动态绑定到某个 Agent，并控制其在页面和首页的显示。

系统预置了若干功能编码（见 AI 总览页「系统功能绑定」下拉列表），新增页面 AI 功能时，如果功能编码已在预置列表中，直接走下方步骤 2~4 即可；如果是**全新的功能编码**，先走步骤 1 在前端创建。

---

### 步骤 1：创建系统功能编码（全新功能时才需要）

如果待添加的功能不在「系统功能绑定」列表中：

1. 进入前端页面：**系统设置 → AI 智能中心 → AI 总览**。
2. 在「系统功能绑定」区域点击「新增系统功能」。
3. 填写功能编码和功能名称，点击「创建」。

**功能编码填写规则：**

- 只能包含英文小写、数字和连字符（如 `treatment-plan-assist`）
- 全局唯一，不能和现有编码重复
- **重要**：前端页面代码里会通过这个编码调用接口获取配置，所以编码一旦确定就不要随意修改，且前后端要保持一致

**功能名称填写规则：**

- 可自由填写，建议用中文业务名称（如「治疗方案辅助」），方便在列表中辨认

> 创建成功后，该功能编码会自动出现在「系统功能绑定」下拉列表中。

---

### 步骤 2：新增 Agent 配置

1. 进入前端页面：**系统设置 → AI 智能中心 → AI 总览**。
2. 在「Agent 配置」区域点击「新增 Agent」，填写：

| 字段 | 说明 |
| ----- | ----- |
| 功能名称 | 如「治疗方案生成」 |
| AgentKey | 唯一标识，如 `treatment-plan-agent` |
| 用途位置 | 如「治疗计划页」 |
| Webhook 地址 | n8n 工作流的 Webhook URL |
| 响应类型 | `json`（一次性返回）或 `sse`（流式返回） |
| 超时 | 默认 60 秒 |
| 认证类型 | `none` / `bearer` / `api-key` |
| 请求模板 | 发送到 n8n 的请求体模板（JSON），支持变量占位 |
| 快捷指令 | JSON 数组，如 `["生成治疗方案", "评估治疗风险"]` |

1. 保存后，Agent 配置会写入 `ai_agent_config` 表。

---

### 步骤 3：系统功能绑定

1. 仍在 **AI 总览** 页面，滚动到「系统功能绑定」区域。
2. 从下拉框中选择新功能（步骤 1 创建的功能编码会出现在此列表中）。
3. 在「绑定 Agent」下拉框中选择步骤 2 创建的 Agent。
4. 打开「所在页面显示」开关（控制目标页面是否展示 AI 入口）。
5. 如需在首页 AI 下拉框中也显示，打开「首页显示」开关。
6. 点击「保存配置」。

> 系统功能绑定数据存储在 `ai_function_mapping` 表中，当前账户的配置会覆盖系统默认配置。

---

完成以上 3 步后，系统功能编码、Agent 配置、绑定关系全部就绪。接下来只需要在目标页面添加前端入口按钮和调用逻辑即可，无需再操作数据库。

### 步骤 4：前端目标页面接入

在需要接入 AI 功能的 Vue 页面中，需要修改 4 处代码。以功能编码 `your-feature-code` 为例：

#### 4.1 data 中定义状态字段

```javascript
data() {
  return {
    // ... 原有字段 ...
    yourFeatureAgentKey: '',
    yourFeatureVisible: false,
    yourFeatureLoading: false
  }
}
```

#### 4.2 created / mounted 中加载配置

```javascript
created() {
  // ... 原有逻辑 ...
  this.loadYourFeatureConfig()
},

methods: {
  async loadYourFeatureConfig() {
    const accountId = localStorage.getItem('account_id')
    try {
      const res = await axios.get('/api/ai/function-mappings/your-feature-code/agent-key', {
        params: { accountId }
      })
      if (res.data.code === '200') {
        this.yourFeatureAgentKey = res.data.data.agentKey || ''
        this.yourFeatureVisible = res.data.data.isVisibleOnPage === true
      }
    } catch (e) {
      console.error('加载AI配置失败', e)
    }
  }
}
```

#### 4.3 页面中添加入口按钮

```html
<el-button
  v-if="yourFeatureVisible"
  type="primary"
  size="small"
  icon="el-icon-magic-stick"
  :loading="yourFeatureLoading"
  @click="callYourFeatureAI"
>
  AI 新功能
</el-button>
```

#### 4.4 methods 中添加调用方法

```javascript
async callYourFeatureAI() {
  if (!this.yourFeatureAgentKey) {
    this.$message.warning('当前功能未绑定 Agent')
    return
  }
  this.yourFeatureLoading = true
  try {
    const res = await axios.post(`/api/ai/proxy/${this.yourFeatureAgentKey}`, {
      message: '用户输入或业务上下文',
      account_id: localStorage.getItem('account_id'),
      account_name: localStorage.getItem('account_name'),
      // 根据页面需要补充其他业务字段
      patient_id: this.patientId,
      diagnosis: this.diagnosis
    })
    if (res.data.code === '200') {
      const reply = res.data.data.reply || res.data.data.content
      this.$message.success(reply)
    }
  } catch (e) {
    this.$message.error('AI 请求失败')
  } finally {
    this.yourFeatureLoading = false
  }
}
```

#### 4.5 前端代码存放位置参考

| 页面 | 文件路径 |
|------|---------|
| 病历编辑页 | `saas-vue-src/src/views/Manager/MedicalRecordView.vue` |
| 患者详情页 | `saas-vue-src/src/views/Manager/PatientDetailView.vue` |
| 预约控制台 | `saas-vue-src/src/views/Manager/AppointmentView.vue` |
| 回访管理 | `saas-vue-src/src/views/Manager/FollowupView.vue` |

### 步骤 5：测试验证

1. **配置验证**：进入 AI 总览，确认新 Agent 已保存，系统功能绑定已选中该 Agent。
2. **页面显示验证**：进入目标页面，确认 AI 入口按钮根据开关状态正确显示/隐藏。
3. **接口联调验证**：点击按钮，查看浏览器 Network 面板，确认请求发送到 `/api/ai/proxy/{agentKey}`，且后端返回预期结果。

### 步骤 6：快速协作流程（可选）

如果你不想自己写前端代码，完成步骤 1~3 的绑定后，可以直接提供以下信息，由开发助手代写前端入口代码：

```text
功能编码：your-feature-code
目标页面：患者详情页 / 病历编辑页 / 预约视图 / 回访管理 …
按钮文字：AI 分析 / AI 扩写 / AI 推荐 …
发送字段：患者ID、诊断内容、备注、病历文本 …
```

开发助手会：

1. 找到对应页面的 Vue 文件
2. 把加载配置 + 按钮 + 调用方法的代码写进去
3. 启动浏览器验证按钮显示和接口调用正常

> 前提：Agent 的 Webhook 地址已配置好，n8n 工作流能正常响应。

## 常见问题排查

| 问题 | 排查步骤 |
|------|---------|
| 后端无法启动 | 检查 `docker compose logs backend`，确认 MySQL 已启动且 Flyway 无冲突 |
| 前端热刷新失效 | 检查 `docker compose logs frontend`，确认 WebSocket 连接正常 |
| AI 请求无响应 | 确认外部端点 URL 可访问，检查后端日志中的代理请求记录 |
| 数据库迁移失败 | 检查 Flyway 版本冲突，手动执行 `repair` 或清理 `flyway_schema_history` |
| 登录失败 | 确认数据库中存在该用户，密码为明文比对（当前无加密） |
| 接口 404 | 确认 `SpaForwardController` 中已添加对应路由转发规则 |
